# Research Brief — Marketing site + in-app feedback link

Phase 1 of the build pipeline. Feature scope, not a new project.

## Goal

Give FieldMark a public front door. Today the GitHub Pages deploy publishes the
*app itself* at the site root; there is no page that explains what the app is,
who it is for, or why someone should try it. Add a landing page in front of the
app, and close the loop with an in-app way to send feedback.

## Key conclusions

1. **Both in-app pieces are renderer-only.** `openExternal` is already in the
   contract, and `Viewer.load` is already public. Per the cross-platform rule in
   CLAUDE.md this means the feedback link and demo loader ship to Windows, macOS
   and Android for free, with **no `src/preload.js` / `platform-web.js` change**.

2. **Relocating the app to `/app/` is safe.** Every path `build-pwa.js` emits is
   already relative (`start_url: './'`, `scope: './'`, relative icons, SW
   precache resolved against `self.registration.scope`). Serving the same bundle
   from a sub-directory needs no path rewriting.

3. **The service-worker scope moves.** An existing installed PWA scoped at
   `/PDF-Reader/` will not follow the app to `/PDF-Reader/app/`. Install base is
   effectively zero today, so this is the moment to absorb that break. A
   redirect stub at the old root keeps existing bookmarks working.

4. **`verify-pwa.js` hardcodes `dist-pwa/` as the PWA root** and must learn that
   the PWA now lives at `dist-pwa/app/`, plus gain landing-page assertions.

5. **No new dependencies.** The landing page is plain HTML/CSS, consistent with
   the no-bundler convention. `site/` is a static folder copied at build time.

6. **GitHub Pages cannot set response headers.** Noted for the backlog: if OCR
   ever needs multi-threaded WASM (`SharedArrayBuffer` requires COOP/COEP), the
   host would have to move to Cloudflare Pages. Out of scope here.

## External research

- **Positioning.** The measure/takeoff/redline/stamp feature set maps to the
  Bluebeam Revu audience (estimators, GCs, field engineers). Revu is a paid
  annual subscription; "free, offline, no account" is the differentiator.
- **GitHub Pages custom domains** are supported with free HTTPS via a `CNAME`
  file at the published artifact root. The file must survive the build, so it
  belongs in `site/` and gets copied, not hand-placed in `dist-pwa/`.
- **Demo funnel.** An in-browser trial removes the install barrier entirely; the
  PWA already runs fully client-side, so a preloaded sample drawing is the
  cheapest possible "try before you download".

## Open questions (resolved by decision, not blocking)

- **Domain name** — not purchased yet. Ship `CNAME` support driven by an
  optional `site/CNAME` file so the domain can be added later without a code
  change. Do not invent a domain in the copy; link relatively.
- **Product name** — repo is `PDF-Reader`, package is `pdf-signer`, UI says
  "FieldMark". The site standardises on **FieldMark**; renaming the repo and
  package is deferred to `specs/backlog.md`.
